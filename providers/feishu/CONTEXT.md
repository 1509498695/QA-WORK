# Feishu Provider 领域语言

本上下文定义 Feishu Provider 内授权控制面、执行客户端和受控资源操作共同使用的语言。

## 身份与授权

**Feishu Provider**：
独立管理飞书连接、身份、权限与受控资源语义，并以公共能力契约返回状态和证据的能力 Provider。
_Avoid_：lg-feishu、业务 Skill、通用飞书脚本

**飞书租户**：
企业自建应用、用户身份和资源可见范围共同归属的企业边界。
_Avoid_：用户 Profile、知识空间、群聊

**Provider 专用应用**：
只由 Feishu Provider 使用、承载 OAuth 应用身份和回调配置的飞书企业自建应用。
_Avoid_：其他飞书 Provider 的应用、用户身份、业务 Skill 专用应用

**部署绑定**：
Provider 专用应用、准入租户与本地执行客户端身份之间经管理员确认建立的完整配置关系。
_Avoid_：环境变量片段、单个 App Secret、OAuth 用户授权

**Provider Profile**：
一个飞书用户主体及其长期 OAuth 授权状态的稳定逻辑引用；Profile 不向执行客户端暴露 Refresh Token。
_Avoid_：账号密码、最近登录用户、Access Token

**OAuth Scope**：
飞书平台授予一个 Profile 的原子权限；Provider 语义能力必须映射到一个或多个可接受 Scope。
_Avoid_：业务权限、正式写入确认、能力 ID

**语义能力 ID**：
Feishu Provider 对稳定用户意图的私有标识，用于租约申请和 Scope 覆盖判断。
_Avoid_：飞书 Scope、MCP 工具名、HTTP 路径

## 部署单元

**授权控制面**：
持有 Provider 应用身份和 Profile 长期授权、完成 OAuth 生命周期并签发短期租约的安全边界；它不接收或代理文档与表格正文。
_Avoid_：MCP Server、业务数据网关、OAuth 结果页

**MCP Server**：
取得短期租约后直接调用飞书 OpenAPI、执行受控资源操作并返回结构化结果与证据的执行边界。
_Avoid_：授权控制面、Profile 仓库、远端内容缓存

**执行客户端身份**：
MCP Server 向授权控制面证明自身获准申请租约的本地身份；它与飞书用户身份彼此独立。
_Avoid_：Provider Profile、飞书 Access Token、调用方任务引用

**Feishu 私有协议**：
授权控制面与 MCP Server 共享的 capability ID、租约请求、租约交付和执行客户端身份模型。
_Avoid_：公共能力契约、远端 OpenAPI Schema、服务实现

**短期访问令牌租约**：
授权控制面为确定任务、Profile 和语义能力签发的短时访问能力；Access Token 只在授权控制面与当前 MCP 进程内存中存在。
_Avoid_：Refresh Token、跨任务会话、长期凭证副本

## 飞书资源

**飞书资源定位符**：
Feishu Provider 可识别并规范化的 Docx 标识、Docx URL、Wiki URL 或 Sheets URL。
_Avoid_：任意网页地址、任务引用、读取结果

**工作表选择器**：
直接 Sheets URL 中用于稳定指向一个工作表的 `sheet` 查询参数；写入定位必须保留并校验其工作表标识，不能在 URL 规范化时丢弃。
_Avoid_：工作表名称、工作表顺序、Wiki 节点 token

**Docx 资源**：
由文档元数据、完整 Block 序列以及可读取图片和附件组成的飞书文档对象。
_Avoid_：旧版 Docs 推断、Wiki 节点、附件缓存目录

**Wiki 节点**：
知识空间中的导航对象；只有在线解析其真实对象类型和 token 后，才能继续读取对应资源。
_Avoid_：Docx 别名、Sheets 别名、静态 URL 推断

**Sheets 资源**：
由工作簿元数据、有序工作表、网格边界、合并区间、公式和值组成的飞书电子表格对象。
_Avoid_：Bitable、视觉工作簿克隆、本地 Excel 文件

**目标工作簿**：
用户通过直接 Sheets URL 或解析后真实类型为 Sheets 的 Wiki URL 明确指定、用于承载交付工作表的既有工作簿；指定它不表示 Provider 接管整个工作簿。
_Avoid_：受管工作表、来源模板、任意飞书文档

**受管工作表**：
在目标工作簿中由 Provider 新建，或经正式写入授权接管且在写入前再次证明满足空白判定的单个工作表；Provider 登记其工作簿标识、工作表标识、用户主体和初始内容状态，后续写入权限不外溢到同一工作簿的其他工作表。
_Avoid_：整个目标工作簿、未经登记的既有工作表、仅凭链接可编辑的工作表

**受管工作表修订**：
保持已登记工作表的稳定身份和管理主体不变，把它从一个已验证交付状态变更为另一个已验证交付状态。
_Avoid_：首次交付、覆盖任意非空工作表、新建工作表替代原对象

**修订基线**：
受管工作表最近一次已验证交付所对应的完整规范及其语义状态，是下一次修订前无漂移核验的唯一参照；远端内容、结构、冻结设置或受管尺寸只要有一项不一致，修订预览就必须失败并保持远端零写入，Provider 不得静默覆盖或自动合并。
_Avoid_：仅凭远端 revision 号、当前任意内容、未经核验的最新状态

**修订基线双重核验**：
任何实际修订或无变化修订在进入写入授权前，都以飞书 API 回读验证值、公式、合并与冻结状态，并以仅驻当前调用内存的临时 XLSX 导出验证样式和行列尺寸；任一证据不完整均以 `baseline_verification_incomplete` 零写入结束。该临时导出不是本地交付文件。
_Avoid_：只比 remote revision、只验证单元格值、保留 XLSX 为业务文件、基线证据不完整仍继续确认

**修订规范对**：
调用方在每次修订预览中同时提交的 `base_spec` 与 `next_spec`；`base_spec` 的规范摘要必须匹配受管工作表登记中的最近交付摘要，Provider 再以它核验远端无漂移，匹配后才允许为 `next_spec` 建立预览。Provider 只持久化摘要、目标和验证证据，不持久化两份规范正文。
_Avoid_：只提交目标规范、把当前远端内容当作基线、由 Provider 长期保存业务正文

**调用方修订基线资产**：
业务 Skill 在自己的任务暂存区或审计包中按 `registration_ref` 与规范摘要保存的最近一次已交付规范化 JSON；它由 Skill 自动维护并作为下一次 `base_spec`，不属于 Provider 操作状态，也不是 XLSX、导出文件或用户交付物。资产缺失或摘要不匹配时修订以 `base_spec_required` 零写入结束，不得从远端当前内容反推基线。
_Avoid_：要求用户手工保管 JSON、Provider 正文仓库、临时 XLSX、把远端快照直接提升为已认证基线

**修订就绪状态**：
业务 Skill 在 Provider 已返回 `delivered` 后，是否已把同一 `next_spec` 安全提升为下一次修订基线的独立状态；基线保存失败时本次飞书交付仍保持 `delivered`，但必须报告 `revision_ready=false` 与 `baseline_persistence_incomplete`。重试只保存本地基线，不重新写飞书或重复确认。
_Avoid_：把基线保存失败伪装成远端写入失败、在未保存基线时报告修订就绪、为修复本地状态重放远端写入

**工作表放置模式**：
写入预览中不可变的用户意图，只能是接管确定的内容空白工作表，或在目标工作簿中新建工作表；Provider 不根据目标当前状态在两种模式间自动切换。
_Avoid_：自动覆盖、失败后改为新建、按工作表名称猜测

**拟建工作表名称**：
新建模式中由调用方明确提供、写入预览绑定并在正式写入前检查唯一性的名称；名称冲突必须重新预览，Provider 不自动添加后缀或改名。
_Avoid_：Provider 推断的业务名称、最终工作表标识、接管时顺便重命名

**工作表交付规范**：
调用方提交给 Feishu Provider 的单工作表结构化期望状态，包含值、公式、合并、行列尺寸、冻结和白名单样式；它经过规范化后形成写入预览和语义回读共同使用的内容摘要。
_Avoid_：Excel 文件、任意 OpenAPI 请求、业务用例对象、多个工作表的工作簿

**交付矩形**：
工作表交付规范明确声明、由 Provider 完整归一化并逐项回读的连续单元格范围；矩形内未单独覆盖的样式和尺寸也必须落到规范默认值，任何合并不得跨越其边界。
_Avoid_：当前已用区域、只写非空单元格、整个工作簿

**修订退役区域**：
同一受管工作表修订中，`base_spec` 交付矩形减去 `next_spec` 交付矩形所得的有限区域；基线无漂移核验通过后，Provider 必须清除其中的业务内容和样式、拆除进入该区域的旧合并，并把完全退役行列的尺寸恢复为 Schema v1 固定中性值（行高 `24 px`、列宽 `100 px`）。飞书样式清理成功响应不能单独证明样式已中性化，Provider 还需显式写入并以 XLSX 证明受控中性样式；平台导出的 `left` / `top` 对齐可作为该显式中性形态，但旧版 `middle` 等业务对齐仍是残留。清理只改变上一版明确受管的语义，不物理删除行列，也不外溢到上一版交付矩形之外。
_Avoid_：整个矩形外空白区、任意尾部行列、删除工作表行列、保留旧版本残留

**修订前向写入序列**：
用户接受单次确认后，Provider 按“锁定候选版本与扩网格、拆除旧合并、写完整目标矩形并清退役内容、重建样式、写尺寸、写冻结、最后建立新合并、双重验证并前移版本”的固定顺序执行；每一步都有幂等检查点，结果不明时只允许同一操作前向恢复。
_Avoid_：自动回滚、切换目标、重复确认、盲目重放已完成步骤、验证完成前前移版本

**矩形外空白区**：
受管工作表中交付矩形之外必须保持无业务内容的区域；接管既有空白工作表时，Provider 不清除或改写其中仅作用于空单元格的既有样式。行高和列宽按行/列轴生效：交付矩形覆盖的行列属于受管尺寸范围，之后的行高与列宽保持不变。
_Avoid_：Provider 交付内容、需要全量归一化的区域、可忽略的既有公式

**MCP 写入确认**：
正式应用工具通过 MCP elicitation 向当前客户端展示已登记预览摘要，并只根据客户端返回的接受、拒绝或取消动作生成服务端单次授权的交互边界。
_Avoid_：`confirmed=true`、普通聊天文本、OAuth 同意、客户端 Profile 绑定

**单次可见修订确认**：
一次受管工作表修订只向用户展示一次绑定精确目标、`base_spec`、`next_spec` 和退役区域清理摘要的 MCP elicitation；登记匹配、无漂移核验、差异计算、写入、双重回读及同一不可变操作的恢复对账均由流程自动衔接。减少用户交互不删除任何失败关闭条件，只有授权缺失、目标不唯一、基线漂移或规范变化才中止并要求重新处理。
_Avoid_：聊天中重复确认、每个技术检查各弹一次确认、恢复同一操作时再次确认、取消写前用户确认

**修订授权摘要**：
单次修订确认卡片中绑定精确目标、当前与候选受管版本、交付矩形变化、各类语义增删改计数、退役区域精确范围以及完整 `preview_sha256`、基线和目标规范摘要的有界信息；卡片不展开单元格值或公式正文，上层业务预览负责内容审阅。
_Avoid_：完整正文转储、只显示“将更新表格”、省略破坏性清理范围、截短或替换精确摘要

**一体化修订调用**：
调用方以一次高阶工具调用提交 `registration_ref`、`task_ref`、`base_spec` 和 `next_spec`；工具内部仍建立不可变预览和幂等检查点，并自动衔接前置核验、单次 MCP 确认、写入、双重回读与同一规范对的恢复。首次交付既有两阶段工具暂时保持兼容，修订不复用其放置模式和目标选择合同。
_Avoid_：调用方手动编排修订 `preview → apply`、把首次交付工具扩成多态入口、取消内部预览记录、相同恢复操作重复确认

**同任务修订纵切**：
首个修订实现只要求同一调用方任务仍持有摘要匹配的基线规范，完整交付 Provider、Plugin、登记解析和一体化修订合同；它不实现或宣称跨任务自动找回基线，不修改本地独立的 `qa-case-xlsx-local`，也不建立隐藏的全局正文缓存。
_Avoid_：把 Provider 完成报告成跨任务业务集成完成、让 Provider 保存基线正文、扩大本地 Skill 的飞书边界、临时发明全局缓存

**无变化修订请求**：
`base_spec` 与 `next_spec` 规范摘要相同的修订调用；Provider 仍自动证明远端受管语义等于基线，匹配后返回 `no_change` 和当前受管版本，不建立写入授权、不展示确认、不写远端也不追加版本。远端漂移时仍以 `precondition_failed` 零写入结束。
_Avoid_：为零差异弹确认、制造空版本、跳过远端基线核验、把漂移对象报告为无变化

**操作状态库**：
MCP 执行端在既有本机 Provider 命名空间中拥有的持久技术状态，只保存预览摘要、单次授权、幂等步骤、受管工作表登记和恢复墓碑，不保存工作表正文。
_Avoid_：调用方任务暂存区、OAuth 控制面数据库、业务内容缓存

**受管工作表登记**：
把确定 Provider Profile、目标工作簿、稳定工作表标识、建立检查点和初始内容摘要持久关联的最小记录，用于限制后续修订和恢复目标。
_Avoid_：链接收藏、工作表名称索引、整个工作簿所有权

**受管版本记录**：
同一受管登记下按单调版本号追加、且不含工作表正文的不可变交付元数据，至少绑定父规范摘要、目标规范摘要、操作引用、交付证据摘要、飞书 revision 与时间；受管登记只在该版本写入和验证完成后事务性前移当前版本指针。同一登记同时最多存在一个未终结修订。
_Avoid_：覆盖上一版证据、把版本号当作工作表身份、保存单元格正文、允许并发修订争抢当前指针

**受管登记引用**：
首次交付完成后由 Provider 返回、并在同一受管工作表全部后续修订中保持不变的 opaque `registration_ref`；它是修订写入的规范身份，固定关联 Provider Profile、工作簿稳定标识和工作表稳定标识。用户提供的飞书链接只能用于查找或交叉核验这条登记，不能单独授权修订写入。
_Avoid_：一次性 `operation_ref`、工作表名称、仅凭飞书链接写入、每次修订生成新身份

**受管登记解析**：
Skill 根据用户提供的飞书链接，通过只读能力唯一查找当前 Profile 下的受管登记引用；精确工作表链接必须匹配同一稳定工作表，未指定工作表时只在目标工作簿恰好存在一条受管登记时自动选择。零条匹配要求先完成首次交付，多条匹配要求更精确链接，解析本身不产生写入授权。
_Avoid_：要求用户手工保存 opaque 引用、按工作表名称猜测、从多条登记中自动任选、把解析成功当作写入确认

**展示元数据变化**：
工作簿 token 与工作表稳定标识保持不变时，工作簿或工作表名称、工作表索引和排序发生的非受管变化；Provider 自动刷新这些展示字段且不建立受管版本。工作表被隐藏、删除、替换、稳定身份变化或当前主体失去访问能力不属于展示变化，必须阻断修订。
_Avoid_：把名称当作对象身份、因重命名阻断正常修订、向隐藏或已替换工作表继续写入、由修订流程顺便重命名

**临时受管状态**：
新建或接管步骤已经改变远端对象、但全部写入和双重语义回读尚未完成时，操作状态库对该工作表建立的恢复锁；只有同一操作、同一规范摘要的前向恢复可以继续修改它。
_Avoid_：已交付、自动回滚标记、允许任意后续写入

**前向恢复**：
根据已确认的远端检查点跳过已经语义完成的步骤，并只继续同一次交付中尚未证明完成的确定性步骤；它保留已创建或已写入的现场，不能自动删除工作表或清空内容。
_Avoid_：盲目重试、重新预览为另一目标、补偿性删除

**非原子空白接管**：
本机开发纵切在 MCP 确认后立即复核内容空白再开始写入，但因飞书未提供目标 revision 条件写入或工作表锁，复核与首次写入之间仍存在极短并发窗口的受限模式。
_Avoid_：原子比较并交换、并发安全保证、正式多人默认能力

**导出验证快照**：
正式写入后以同一 Provider Profile 临时导出并仅在内存中解析的 XLSX，用于补足原生 Sheets 读取不能回读的目标工作表样式、行高和列宽；它不进入任务暂存区或操作状态库。
_Avoid_：正式交付文件、Provider 内容缓存、整簿业务来源

**内容空白**：
普通、可见工作表的一项可证明前置条件：完整读取覆盖其网格后，所有单元格都只包含空值或空字符串，且不存在公式、富文本、链接、提及或合并区间；行列尺寸、冻结和空单元格样式不属于内容空白判定。
_Avoid_：视觉上看似空白、未完整读取、样式层完全为空

**资源解析**：
在不读取正文的情况下识别定位符目标、资源类型和规范标识的操作；Wiki 的真实对象解析属于后续在线步骤。
_Avoid_：内容读取、权限预检、URL 字符串截取即完成

**只读资源快照**：
一次调用中从飞书实际对象读取的结构化内容、修订和完整性证据；快照不由 Provider 跨任务持久化。
_Avoid_：实时链接、Provider 缓存、业务交付物

**受管交付对象**：
由 Feishu Provider 为一次正式交付登记主体和初始状态、后续只允许通过同一受控流程修订的资源单元；Docx 以整个文档为单元，Sheets 以受管工作表为单元。
_Avoid_：任意既有对象、来源对象、只读模板

**读取不完整**：
资源存在未支持对象、未解析内容、安全上限截断、分页异常或修订变化，使快照不能证明覆盖目标全部语义的状态。
_Avoid_：读取失败、可忽略警告、部分成功即完整
