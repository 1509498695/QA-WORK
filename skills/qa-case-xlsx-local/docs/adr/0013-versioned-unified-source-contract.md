# 统一来源契约采用 v2 并保留本地 v1

`qa-case-xlsx-unified` 采用新的 v2 通用来源契约，以 `sources[]` 表达来源并由每项 `origin=local|feishu` 保留真实来源类型；`qa-case-xlsx-local` 对外继续使用既有 v1 `files[]` 契约，通过单向适配器进入可复用的统一处理核心。适配过程必须保留原来源身份、哈希和证据定位，且不得把飞书快照反向伪装成 v1 本地文件；这以维护两个入口契约及适配测试为代价，避免破坏现有纯本地调用，也避免让统一核心长期理解两套输入形状。

## Considered Options

- 原位扩展 v1 `files[]`：拒绝，因为现有本地入口和校验器把每项定义为真实本地文件，扩展会改变既有合同含义。
- 将飞书快照编码成 v1 本地文件：拒绝，因为临时落盘路径不能代表远端来源身份、修订、权限和完整性状态。
- 让统一核心永久同时处理 v1 与 v2：拒绝，因为兼容分支会渗透生成、证据和审计流程，难以形成单一内部语义。
