# 公共能力采用隔离 Provider 架构

工作空间公共能力层采用一份稳定的公共能力契约，并按外部系统拆分独立的 Provider Plugin/MCP；飞书、SVN 及后续外部系统分别拥有自己的工具命名、身份授权、配置、发布和故障边界，业务 Skill 只通过公共能力契约编排所需能力。各 Provider 可以位于同一代码仓库并复用无外部系统语义的公共核心，但不得合并成持有全部凭证和权限的万能 MCP；这以额外的包管理和契约版本治理，换取最小权限、故障隔离与后续扩展能力。

## Considered Options

- 单一万能 MCP：拒绝，因为无关系统的工具、凭证、权限与故障会共享同一暴露面。
- 各业务 Skill 直接实现外部系统客户端：拒绝，因为认证、审计和恢复语义会重复并随业务 Skill 分叉。
