# 首个飞书 OAuth 最小纵切

> 本文件保留 2026-08-19 首次 OAuth 验证的历史边界。Refresh Token Profile、任务租约和 Docx 只读 Provider 的当前状态见 [0003-first-feishu-docx-read-provider-slice.md](./0003-first-feishu-docx-read-provider-slice.md)。

## 当前状态

- 本机服务、配置预检、OAuth 跳转、单次状态存储、飞书 Token 交换客户端、用户与租户校验及安全结果页已经实现。
- 自动测试 `14 passed`，字节码编译、`uv lock --check`、敏感模式和尾随空白检查通过。
- 已用测试配置启动 `127.0.0.1:3000`，验证健康检查、状态页、首页和飞书授权重定向后正常关闭。
- 已使用本项目专用飞书应用完成真实 OAuth、租户准入校验和用户身份只读回读，最终结果为 `verified`；真实租户与 Profile 标识不写入版本化文档。

## 已确认的零输入部署边界

- 首次部署由管理员建立一次“控制面部署绑定”，普通用户和日常启动不再输入应用配置。
- 首版通过仅限本机管理员访问的“控制面配置台”建立和维护该绑定；普通 OAuth 用户与业务 Skill 不显示该入口，也不能提交配置。
- 配置台从统一的“能力平台管理门户”进入；首版门户只展示 Feishu Provider，未来 SVN 等 Provider 各自拥有配置校验、状态与密钥存储，门户不建设共享万能配置表或跨 Provider 密钥库。
- 可写配置台只在管理员显式开启的单次“控制面配置会话”中短时存在，保存成功、取消或超时即关闭；日常 OAuth 服务只提供脱敏只读状态。
- 控制面配置会话与正常 OAuth 服务互斥：管理员先停止服务，配置经完整校验后原子替换本机部署绑定，再由新进程加载；校验或保存失败时保留上一份有效配置。
- 首版配置台只允许编辑飞书 App ID、App Secret 和准入 `tenant_key`；回调地址、Scope、监听地址与端口只读展示，状态过期时间和请求超时等工程参数不进入配置台。
- 修改任一字段时仍以完整三字段配置校验并原子替换；删除只表示“控制面部署解绑”，同时移除整份普通配置与 DPAPI 密文，不允许形成缺少单个必填字段的半配置状态。
- 部署解绑后正常 OAuth 服务拒绝启动，且不自动回退租户发现或沿用旧配置；管理员必须重新建立完整部署绑定。
- 首版部署解绑只删除本机状态，不自动删除飞书应用、轮换 App Secret 或撤销用户授权；配置台必须明确提示“本机删除不等于飞书远端撤销”，远端处置以后作为独立高风险操作设计。
- 部署解绑只能从短时管理员配置会话中的网页发起；网页提交后真实删除底层本机配置与 DPAPI 密文，不提供仅隐藏页面条目但继续保留有效绑定的伪删除。
- 删除确认页展示确定的本机配置路径、App ID、准入租户和“已保存密钥”状态但不显示 Secret，并明确提示本机与远端边界；只有管理员输入精确短语 `删除本机部署绑定` 后才可提交。
- 删除完成必须重新回读普通配置与 DPAPI 密文均不存在，并将控制面报告为未配置；任一目标仍存在时不得报告解绑成功。
- App Secret 由管理员首次隐藏输入后，以 Windows DPAPI 当前用户保护的密文保存在版本库之外；后续启动自动解密。
- 修改页面永不回显现有 App Secret 或 DPAPI 密文；默认保留现有 Secret，只有管理员显式选择替换并两次输入一致时才写入新密文，留空不表示删除。
- App ID 或准入 `tenant_key` 变化属于 Provider 应用或租户身份边界变化，必须使旧 Profile 及其授权证明失效并要求重新 OAuth；不得静默沿用旧身份。当前纵切因配置模式与服务互斥而清空全部进程内 OAuth 状态和结果。
- DPAPI 密文只允许创建它的 Windows 用户在本机使用，不作为跨机器备份、共享凭证或生产 KMS 的替代品。
- 源码、版本化配置、普通本机配置、命令历史、日志和任务产物均不得出现明文 App Secret。
- 该存储方式是首版本机控制面的可替换部署实现；正式中央服务部署时改由选定的集中密钥管理设施托管，不改变 Provider 或业务 Skill 契约。

## 目标

用独立于 `lg-feishu` 的飞书企业自建应用和本机独立运行服务，先证明一个用户能够完成真实 OAuth、通过回调建立已验证主体，并以该用户身份完成一次只读验证调用。该纵切是开发验证，不宣称生产就绪，也不一次实现全部目标安全架构。

## 本轮包含

- 一个准入飞书企业租户、一个专用应用和一个用户 Profile。
- 本机独立服务中的 OAuth 发起、单次 `state` 校验、回调和授权码交换。
- 从飞书实际返回中校验用户主体与准入租户，不接受客户端自报身份。
- 使用内存中的 User Access Token 完成一次最小真实只读验证调用。
- App Secret 只由运行服务从仓库外配置读取；OAuth Code 和 Token 不进入 URL 日志、任务目录或普通审计。
- 成功、用户拒绝、`state` 失效、回调失败和租户不匹配的最小结构化结果。

## 本轮不包含

- 客户端证书、mTLS、客户端登记、客户端 Profile 绑定和绑定确认页面。
- 任务级令牌租约、长期 Token 持久化、自动刷新、普通撤销和紧急隔离。
- 多租户、多人管理台、正式 HTTPS 托管、多实例高可用或灾备体系。
- 私有 CA、KMS、通用策略引擎、自动风险检测、告警通知和复杂审批流。
- Docx、Wiki、Sheets 全量读写、本地正式交付、SVN Provider 或业务 Skill 迁移。
- 将开发验证结果表述为生产就绪或多人可用。

## 完成证据

- 使用本项目专用 App ID 打开真实飞书 OAuth 页面并命中精确登记的本机回调。
- 单次 `state` 被正确消费，重复、过期或不匹配回调被拒绝。
- 回调取得的用户主体和租户与飞书实际返回一致，非准入租户不建立 Profile。
- User Access Token 只在服务进程内存中用于一次真实只读调用，结果中不出现 Token。
- 服务退出后不留下可恢复 Token；日志和仓库敏感信息扫描通过。

## 暂缓决策

- ADR 0026 至 ADR 0032 定义的客户端身份、绑定、任务租约和撤销机制，待最小 OAuth 纵切通过后按顺序实现。
- 正式托管平台、生产域名、数据库产品、KMS 产品、HA 和可用性目标。
- 证书签发与轮换、绑定固定有效期、多人管理角色和跨租户模型。
