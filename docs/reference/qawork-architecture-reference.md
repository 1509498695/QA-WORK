# QAWORK 架构参考边界

## 参考基线

本设计于 2026-08-19 只读检查 `D:\project\QAWORK\qa_workspace` 的提交 `2c4675e`。参考范围包括已跟踪的 `AGENTS.md`、`workspace.yaml`、公共插件收敛架构、ADR 0014、任务目录实现、飞书交付合同及其测试。该工作树中的根 `CONTEXT.md` 当时为未跟踪文件，不作为本设计依据；本次检查没有修改 QAWORK。

## 可借鉴模式

- 使用 `workspace.yaml` 中稳定且唯一的 Workspace ID 作为向上发现和边界校验真源，不根据目录名猜测身份。
- 把安装与注册、Profile 授权、任务级能力就绪和一次正式写入授权拆成不同状态，不以插件存在推断业务能力可用。
- 原始正文、表格、图片和附件归属调用方任务目录；业务产物与来源位于同一任务边界，便于形成完整证据链。
- 业务层只构建命名语义计划，Provider 负责 transport、鉴权、分页、物理资源定位、权限复验和回读；禁止业务脚本复制通用 Feishu gateway。
- 用稳定 `operation_id`、内容哈希、预览摘要和确认执行绑定同一操作；图片等本地资源使用任务相对路径及内容哈希，并拒绝任务边界外路径和符号链接逃逸。
- 受管对象通过逻辑名和 Provider 私有 registry 访问，登记状态与当前可写状态分离；物理 URL、Token 和资源 ID 不进入业务计划、任务记录或仓库。
- 跨 Skill 协作使用版本化文件或 JSON 进程合同，不通过跨 Skill 私有 Python import 形成隐式耦合。
- 用结构、安全、路径、确认摘要和业务计划测试持续锁定架构边界，而不只依赖文档约定。

## 不复制的部分

- 不复用 `lg-feishu` 的 MCP、运行时、私有 registry、凭证、工具名或安装缓存；飞书 Provider 在本能力工作空间独立实现和发布。
- 不复制 QAWORK 的 QA 业务路由、项目规则、角色策略或“必须飞书交付”口径；本设计由用户输入自动识别来源，并由用户在预览后选择和确认飞书或本地交付。
- 不把 QAWORK 的单仓固定 `tasks/` 根目录直接提升为公共约束。未来业务 Skill 可以位于不同目录，任务物理位置仍应归调用方所有。
- 不原样复制当前 `qa_workspace.task` v1。它提供了轻量任务脚手架，但尚未表达不可变快照版本、Provider Profile 绑定、预览与授权摘要、交付状态、清理状态和恢复墓碑。
- 不把 QAWORK 当前插件版本、Marketplace revision、模板逻辑名或已登记资源状态当成本工作空间的就绪证据。

## 对本设计的直接约束

- 公共任务合同应保留 QAWORK 的任务归属和路径逃逸防护，同时改为适配多目录业务 Skill 的逻辑任务引用。
- 本地构件能力负责创建和解析任务边界；Provider 不接受未经验证的任意绝对输出路径。
- Feishu Provider 与未来 SVN Provider 必须共享公共 envelope、错误语义和任务引用合同，但各自独立拥有身份、权限、状态及语义工具。
- QAWORK 仅作为已验证模式的参考输入；任何复用都必须在本工作空间形成自己的契约、测试和 ADR。
