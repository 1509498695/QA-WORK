# 任务令牌租约最长十分钟并在续租时失败关闭

ADR 0030 定义的每份任务级短期访问令牌租约，其平台有效期最长为十分钟，并且不得超过承载的飞书 User Access Token 剩余有效期。授权控制面可以根据剩余 Token 有效期、风险状态或运维策略签发更短租约，但不能延长十分钟上限；若底层 Token 不足以支撑安全租约，控制面应先在内部完成刷新和状态校验，而不是把 Refresh Token 或刷新职责交给执行客户端。

同一 `task_ref` 可以在任务尚未结束且仍需要原语义能力时自动续租，不要求用户重复批准未变化的客户端 Profile 绑定或 OAuth Scope。每次续租都视为新的租约决策，必须重新验证 `tenant_ref`、mTLS 客户端状态、Profile 状态、绑定修订、请求能力集合和实际 Scope，并生成新的 `lease_ref` 与审计记录；旧租约不能作为跳过检查的续租凭据，也不能因底层飞书 Token 值未变化而继续延长。

飞书授权控制面不可用时，客户端可以在原任务、原 Profile、原能力集合内继续使用尚未到期的当前租约，直至平台租约到期、飞书 Token 到期、任务结束或 Provider 进程退出中的最早时点。所有新任务租约和续租必须返回失败关闭状态，不得延长本地计时、复用历史租约、从磁盘恢复 Token 或回退到本机 App Secret 和 Refresh Token。控制面恢复后必须按完整规则重新签发，不补发故障期间假定有效的租约。

十分钟是本平台对可信执行客户端的最大使用窗口和正常撤销传播上限，不改变飞书 Bearer Token 自身的实际有效期。控制面、客户端和审计不得声称平台租约到期会使已泄漏 Token 在飞书资源服务器立即失效；需要提前终止底层 Token 时必须进入 ADR 0032 的紧急 Profile 隔离流程。

## Considered Options

- 租约直接沿用飞书 Token 的完整有效期：拒绝，因为设备、绑定或任务状态变化后会留下过长的客户端使用窗口。
- 每次 Feishu API 调用前在线检查控制面：拒绝，因为分页、附件传输和语义回读会被控制面短时故障逐请求中断，也会把授权服务变成所有业务流量的同步中介。
- 控制面故障时无限延长当前租约：拒绝，因为客户端会自行创造服务端从未批准的授权时间，撤销和审计边界失效。
- 控制面故障时立即中止所有当前操作：拒绝，因为已经开始的短时、只读或回读操作会在可控十分钟窗口内无必要地失败，且不能撤回客户端已经取得的 Bearer Token。

## Consequences

- 租约响应必须同时给出服务端签发时间、平台到期时间和飞书 Token 实际到期时间；客户端使用最早到期时间并依赖单调计时，不能通过修改本机墙上时钟延长租约。
- 自动续租只能发生在同一任务和不扩大的能力集合中；Profile、任务或能力变化必须重新预检并按需进入绑定或 OAuth 授权流程。
- `control_plane_unavailable`、`lease_expired`、`client_revoked`、`binding_changed` 和 `auth_required` 必须是可区分状态，业务 Skill 不得把它们统一处理为可盲目重试错误。
- 正常情况下，可信客户端对客户端或绑定撤销的最大剩余使用窗口不超过十分钟；底层 Token 泄漏与跨客户端紧急停用遵循 ADR 0032。
- 控制面可用性目标和重试退避属于部署运维决策，但不能改变新租约与续租失败关闭的安全语义。
