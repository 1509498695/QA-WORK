# 使用两级 Workspace 清单和本机路径绑定

公共能力平台和调用方 Workspace 分别拥有自己的身份清单。`D:\project\work\workspace.yaml` 是能力平台清单，声明稳定平台 ID、清单 schema、公共契约版本、可发现 Provider 与语义能力目录；每个调用方 Workspace 在自身根目录维护成员工作空间清单，声明稳定成员 ID、目标能力平台 ID、兼容契约范围、相对任务根和所需能力。两类清单都只保存可审核的逻辑声明，不保存凭证、Provider 物理资源 ID、用户绝对路径或本机账号状态。

跨目录成员关系由仓库外的当前用户本机成员登记批准。登记将平台 ID 与成员 ID 绑定到各自经过解析的真实清单位置，并保存身份和任务边界字段的摘要；成员清单声明目标平台只是加入请求，不能单独构成可信成员关系。执行任务时先从调用方当前位置向上查找唯一成员工作空间清单，再通过本机登记解析能力平台，最后双向核对平台 ID、成员 ID、schema、契约兼容范围和任务边界，不根据目录名称、共同父目录、最近使用记录或全盘扫描猜测。

平台清单不需要提交每台机器的成员绝对路径，也不强制把所有业务 Skill 移入平台仓库。成员身份、清单位置或任务根边界发生变化时，原登记失效并返回 `workspace_registration_required` 或 `workspace_boundary_changed`；普通能力需求版本变化只触发兼容预检，除非同时改变身份或任务边界。

## Considered Options

- 只使用能力平台根目录的一份 `workspace.yaml`：拒绝，因为它无法为外部目录中的调用方建立独立身份、任务所有权和能力需求。
- 在平台仓库提交所有成员的绝对路径：拒绝，因为路径属于本机状态，会泄漏用户目录并在其他机器上失效。
- 成员清单写出平台路径后直接信任：拒绝，因为任意目录可以伪造清单并请求访问其他任务或 Provider 能力。
- 自动扫描磁盘发现所有成员 Workspace：拒绝，因为扫描范围不可控、身份可能冲突，也没有形成用户批准的成员关系。

## Consequences

- 能力平台和成员 Workspace 的清单 schema 分别版本化，但身份字段和兼容检查遵循公共契约。
- 同一成员 ID 解析到多个物理清单、清单位于重解析路径或登记摘要不匹配时必须失败关闭，不自动选择其中一个。
- 本机成员登记属于 ADR 0013 定义的本机私有状态，应支持查看、撤销和重新登记，但不得包含外部系统凭证。
- 业务 Skill 可以随调用方 Workspace 独立迁移；迁移后只需重新建立本机路径绑定，不改变稳定成员 ID 或任务合同。
