# 先在本机单用户边界验证 Feishu 受控写入

Feishu Provider 的首个写入纵切继续运行在现有 `local-dev-v0`：使用 localhost 授权控制面、DPAPI 保护的部署绑定与 Provider Profile，以及最长十分钟的任务租约。该纵切仅用于本机单用户开发验证，Provider 能力声明和 Plugin 必须继续明确 `development_only=true`；它不构成正式中央部署、多人接入或生产就绪证明。

开发边界不降低写入安全语义。远端变更只能使用用户委托身份，且必须限定为新建或修订受管交付对象，依次完成不可变写入预览、绑定预览的短期单次正式写入授权、幂等检查点、资源类型专属语义回读和结果不明时的恢复对账。自动化测试只使用模拟 OpenAPI；任何真实飞书冒烟写入都需要另行确认确定目标和测试内容。

Feishu Sheets 纵切中的受管交付对象按 ADR-0045 收窄为用户指定目标工作簿中的一个受管工作表；目标工作簿本身以及同簿其他工作表不进入写入授权范围。

本 ADR 只调整实施顺序，不取代 ADR-0024。稳定 HTTPS、mTLS 执行客户端身份、浏览器客户端 Profile 绑定、持久审计、撤销和多人隔离仍是正式生产部署的前置门槛；在这些门槛完成前，不得把本机写入纵切升级为正式 v1 或扩大到多人使用。

## Considered Options

- 在实现任何写入前先完成正式中央控制面：拒绝，因为会把首次资源写入、授权服务生产化和多人治理合并为一个无法独立验证的风险面。
- 将 localhost 与 DPAPI 纵切直接视为正式写入能力：拒绝，因为它没有实现 ADR-0024 至 ADR-0029 要求的稳定服务和客户端身份边界。
- 在开发纵切中省略预览、单次授权、回读或恢复：拒绝，因为这些是远端副作用的正确性边界，而不是生产部署附加项。

## Consequences

- 新增写入 Scope 后，既有 Provider Profile 必须重新 OAuth；已有只读授权不能静默扩大。
- Plugin 只有在写入工具合同、模拟测试、自包含 runtime 和新任务加载全部验证后才能声明 `Write`，但仍保留开发态标记。
- 正式生产化必须单独提交实施计划和验收证据，不能由本机真实写入成功推断完成。
