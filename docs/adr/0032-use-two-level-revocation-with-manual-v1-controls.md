# 使用两级撤销并保持首版处置最小化

飞书授权控制面提供普通撤销与紧急 Profile 隔离两种明确处置。普通撤销针对确定 `client_ref` 或客户端 Profile 绑定，立即阻止该对象的新租约与续租；可信客户端已取得的任务租约最多按 ADR 0031 运行至十分钟上限，不扩大影响到其他客户端绑定或 Profile。

怀疑客户端私钥、User Access Token、Refresh Token 或 Profile 授权链泄漏时，执行紧急 Profile 隔离：先停用涉事客户端或绑定，再将受影响 `profile_ref` 标记为 `reauth_required`，阻止所有客户端为该 Profile 取得新租约，并销毁控制面持有的该 Profile User Access Token 与 Refresh Token。若已经验证飞书提供适用且结果可回读的撤销能力，则同时调用；否则必须明确报告底层 Bearer Token 可能仍持续到飞书实际到期，不能把本地销毁表述为远端即时失效。

首个授权纵切只实现管理员可明确触发、可回读状态和可审计的最小处置入口，不建设自动风险检测、通用策略引擎、实时推送、告警编排或复杂审批台。紧急隔离完成后必须由 Profile 用户重新 OAuth 并重新检查既有客户端绑定，不能静默恢复旧长期凭证。

## Considered Options

- 所有撤销都只等待十分钟租约到期：拒绝，因为长期凭证或 Bearer Token 泄漏需要阻止刷新和后续跨客户端签发。
- 任一客户端撤销都删除整个 Profile：拒绝，因为普通设备退役不应中断同一用户的其他可信客户端。
- 首版直接建设自动威胁检测和响应平台：拒绝，因为当前目标是先跑通授权链路，手动、确定、可审计的两级动作足以验证边界。
- 本地删除 Token 后报告飞书侧已经失效：拒绝，因为 Bearer Token 的远端有效性必须由飞书实际撤销结果或到期事实证明。

## Consequences

- 普通撤销返回对象级状态；紧急隔离返回 Profile 级状态、受影响绑定与客户端摘要、凭证销毁结果以及远端撤销是否已验证。
- `client_revoked`、`binding_revoked` 和 `profile_reauth_required` 必须可区分，且都阻止对应的新租约与续租。
- 首版允许通过受保护的管理员命令或最小管理端点触发，不要求先建设完整管理 UI；具体入口随首个授权纵切实现选择。
- 自动检测、通知、批量处置、跨租户事件和复杂恢复编排推迟到真实多人运行需求出现后再设计。
