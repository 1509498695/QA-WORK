# 写入结果不明时先恢复对账

每次正式远端写入在产生副作用前保存幂等检查点，并按 `not_started → applying → delivered` 跟踪状态；请求超时、连接中断或响应无法证明结果时进入 `possibly_modified`，锁定同一授权和目标，禁止盲目重试、新建替代对象或开始另一项写入。Provider 必须先对原对象执行恢复对账：回读证明原操作已完整落地则转为 `delivered`；证明完全未修改且原授权、目标状态和内容仍有效时，才可恢复同一次操作；仍无法判定则进入 `recovery_required` 并等待明确处理。

## Considered Options

- 将所有超时视为失败并自动重试：拒绝，因为原请求可能已经修改远端状态，重试会产生重复对象或重复内容。
- 超时后直接新建另一个交付对象：拒绝，因为这会分叉受管对象身份，并把未知结果伪装成一次新成功。
- 一律自动回滚到写前快照：拒绝，因为无法确认当前远端状态时，回滚本身也是未经确认的新写入，可能覆盖并发变化。

## Consequences

- 只有能证明副作用尚未开始或服务端明确返回未修改的瞬时错误，才允许普通自动重试。
- 恢复对账是同一次授权操作的只读延续，不需要新增授权；一旦目标状态、内容或执行主体变化，必须重新预览和确认。
- `possibly_modified` 和 `recovery_required` 都不得被业务 Skill 映射为 `failed_no_change` 或 `delivered`。
