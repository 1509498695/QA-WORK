# 每个执行客户端使用独立证书身份接入授权控制面

每个 Feishu Provider 执行客户端安装实例必须拥有独立的非对称密钥和 X.509 客户端证书，并在一次性管理员批准的登记流程后取得稳定 `client_ref`。客户端私钥只保存在当前设备的操作系统受保护凭证或证书存储中，不得进入仓库、Workspace 清单、任务目录、日志、MCP 正文或可复制配置；不同设备、操作系统用户和 Provider 安装实例不得复用同一私钥或证书。

登记时由客户端本地生成密钥并提交公钥证明，授权控制面将证书身份绑定到确定的 `tenant_ref`、`client_ref`、安装实例说明和生命周期状态。一次性登记凭据只用于建立该绑定，成功或过期后立即失效，不能作为长期调用凭据。登记完成后，客户端必须通过双向 TLS（mTLS）向授权控制面证明对应私钥的持有；共享 API Key、仅依赖网络位置或业务 Skill 自报 `client_ref` 都不能构成客户端认证。

执行客户端身份与 Provider Profile、飞书用户 OAuth 和正式写入授权相互独立。客户端证书只证明“哪个受登记的 Provider 实例正在请求”，不会证明“它可以使用哪个用户 Profile”，也不会把飞书签发的 `user_access_token` 变成证书绑定令牌；Profile 使用权遵循 ADR 0027 的显式客户端 Profile 绑定，正式写入遵循 ADR 0008。客户端被撤销后，控制面立即拒绝其认证和新令牌租约，其他客户端和用户 Profile 的登记不因此失效；已经交付到该客户端内存中的飞书短期令牌按其实际有效期和单独定义的应急策略处理。

## Considered Options

- 所有执行客户端共享一个 API Key：拒绝，因为泄漏后无法定位或只撤销单台设备，也无法可靠审计实际调用实例。
- 使用每客户端独立对称密钥：拒绝，因为服务端必须持有可直接冒充客户端的共享秘密，登记、轮换和泄漏隔离弱于非对称私钥持有证明。
- 只依赖 HTTPS 服务端证书和源 IP：拒绝，因为它们能保护服务端与传输链路，但不能为每个客户端实例提供稳定、可独立撤销的身份。
- 把飞书用户 OAuth Token 当作客户端身份：拒绝，因为用户委托与设备身份的主体、生命周期和撤销范围不同，也会让长期客户端准入依赖临时用户 Token。

## Consequences

- 授权控制面必须保存客户端证书或公钥指纹、`client_ref`、`tenant_ref`、登记来源、状态、有效期、轮换关系和撤销审计，不保存客户端私钥。
- TLS 入口必须验证客户端证书，并将验证后的证书身份传递给应用层；应用层不得信任客户端自行提交的证书头、`client_ref` 或租户字段。
- 客户端预检必须分别报告本机私钥可用、证书有效、服务端信任链有效、登记状态有效和 mTLS 握手成功，不能以普通 HTTPS 健康检查替代。
- 证书轮换必须保持新旧证书与同一 `client_ref` 的可审计关系，并允许单客户端撤销；具体 CA 产品、证书有效期、自动轮换窗口和应急处置流程另行决策。
- mTLS 保护的是客户端到授权控制面的身份和令牌交付链路；Feishu Provider 收到飞书短期令牌后仍必须仅在内存中使用，并遵循 ADR 0023 的禁止持久化约束。
