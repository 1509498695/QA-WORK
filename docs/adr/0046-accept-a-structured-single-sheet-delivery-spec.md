# Feishu Sheets 写入接收结构化单工作表交付规范

Feishu Provider 的首个 Sheets 写入纵切接收一个受限、版本化的单工作表交付规范，而不接收本地 Excel 路径、工作簿字节或任意飞书 OpenAPI 请求。规范表达一个工作表的期望语义状态：值、公式、合并区间、行高、列宽、冻结行列，以及白名单内的字体、颜色、填充、边框、对齐和换行样式。Provider 在产生预览前完成严格校验和确定性规范化，并使用同一规范生成内容摘要、执行远端操作和逐项语义回读。

首版明确不支持图片、图表、批注、条件格式、数据验证和一次交付多个工作表。输入包含未知字段、重叠或非法结构、超出安全上限的范围，或任何未声明支持的资源语义时必须在预览前失败；不得删除字段、近似转换或以警告形式静默降级。远端平台规范化允许的差异必须由资源专属比较规则明确列出，不能靠忽略回读不匹配实现成功。

该交付规范属于 Feishu Provider 的公开语义操作合同，公共能力契约只承载 Provider 中立的状态、证据、预览授权和交付结果包络，不吸收飞书私有请求结构。业务 Skill 负责把自己的业务对象映射为交付规范；Provider 不理解 A:J 用例字段或其他业务规则。现有 `qa-case-xlsx-local` 继续保持纯本地边界，不依赖或调用本能力。

## Considered Options

- 直接上传或导入本地 Excel：拒绝，因为会把本地文件访问、Excel 兼容、工作簿多对象语义和飞书写入耦合进 Provider，并扩大未声明的转换差异。
- 接收原始 OpenAPI 路径与请求体：拒绝，因为会绕过受控语义、权限最小化、预览摘要和资源专属回读。
- 首版完整复刻 Excel 全部能力：拒绝，因为图片、图表、条件格式等各自需要额外上传、定位、恢复和回读语义，无法在首个写入纵切中可靠证明。

## Consequences

- 必须为交付规范定义独立 Schema 版本、确定性序列化、坐标和范围规则、安全上限及严格测试。
- 值与公式必须有无歧义的类型表达；样式只允许明确白名单，未知属性一律拒绝。
- 写入成功不能由请求响应推断，必须回读规范声明的值、公式、合并、必要样式、行列尺寸与冻结状态并比较语义签名。
- 若未来增加图片、图表、批注、条件格式、数据验证或多工作表交付，需要扩展版本化规范并补充对应权限、恢复和回读设计。
