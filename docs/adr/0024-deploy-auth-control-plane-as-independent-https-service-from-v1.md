# 首版即独立部署飞书授权控制面

飞书授权控制面从首版起就是具有稳定 HTTPS Origin、已登记 OAuth 回调地址和持久化私有状态的独立服务；本机 Feishu Provider MCP 只是第一个 Provider 执行客户端，不承载、启动或拥有控制面。首版可以是单实例且只登记一个本机客户端，但该客户端仍须按 ADR 0026 独立登记并通过 mTLS 认证；客户端 Profile 绑定按 ADR 0029 在同一稳定 Origin 的浏览器页面确认。服务和数据边界不得嵌入 MCP 子进程、Codex 会话或调用方 Workspace。

本机容器或临时地址只用于开发和自动化测试。正式 OAuth 验收必须经过预期部署环境的稳定域名、真实回调、持久存储和重启恢复检查；临时隧道、进程内回调或一次性公网地址不能作为正式就绪证据。具体云厂商、内部服务器、容器平台、数据库产品和高可用拓扑不由本 ADR 选择。

## Considered Options

- 首版把控制面嵌入本机 MCP，后续再迁移中央服务：拒绝，因为 App Secret、Refresh Token、Profile 身份和 OAuth 回调都会发生高风险迁移，客户端协议也会被单机假设锁定。
- 正式环境继续使用临时公网隧道：拒绝，因为回调 Origin、证书、可用性和访问边界不稳定，无法作为长期授权入口。
- 首版直接建设多实例高可用集群：拒绝，因为当前只有一个执行客户端，先建立稳定服务与持久化合同即可，多实例协调可以在真实负载前单独设计。

## Consequences

- Feishu Provider 的本地安装不再等于授权控制面可用；预检必须分别验证服务身份、服务端 TLS、客户端证书与 mTLS、回调配置和持久状态版本。
- 控制面升级必须保持 Profile、Refresh Token、客户端登记和审计记录的兼容迁移，不能通过重建服务丢弃用户授权。
- 正式备份不得包含明文凭证，恢复演练必须证明加密材料和状态可以一致恢复；具体备份密钥方案另行决策。
- 后续同租户多人接入只扩展用户和客户端登记，不搬迁首版的应用凭证或回调 Origin；跨租户接入遵循 ADR 0025 的独立演进门禁。
