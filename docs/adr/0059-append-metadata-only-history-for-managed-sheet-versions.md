# 为受管工作表版本追加不含正文的历史记录

每个受管工作表登记保留稳定目标和一个当前版本指针；首次交付建立版本 1，之后每次修订为同一 `registration_ref` 追加单调递增的不可变版本记录。版本记录只保存父规范摘要、目标规范摘要、`operation_ref`、交付证据摘要、飞书 revision、状态与时间，不保存工作表正文。只有该版本完成远端写入及双重语义验证后，状态库才在同一事务中把受管登记的当前版本指针前移。

同一受管登记同时最多允许一个未终结修订。新请求必须证明其 `base_spec` 摘要等于当前版本目标摘要，并通过比较并交换方式占用下一版本；否则以写冲突零写入结束。重复提交相同登记、任务、基线摘要和目标摘要时恢复原操作，而不是创建竞争版本。版本号只用于审计和并发控制，稳定对象身份始终是 `registration_ref`。

## Considered Options

- 每次修订只覆盖登记中的最新摘要和证据：拒绝，因为会丢失父子关系、既有交付证据和部分失败恢复所需的审计链。
- 在版本记录中保存完整规范正文：拒绝，因为修订正文继续由调用方业务 Skill 拥有，Provider 状态库只承担最小技术元数据。
- 允许同一登记并行建立多个候选版本：拒绝，因为两个候选都可能从同一基线出发并相互覆盖，且无法安全合并飞书上的副作用。

## Consequences

- 操作状态库需要版本化迁移，为受管登记增加当前版本指针，并新增受管版本历史及每登记一个活动修订的唯一约束。
- 首次交付、修订和恢复结果都返回 `managed_version`；用户无需输入或管理它。
- 当前指针更新失败或证据尚不完整时不得报告新版本生效；已经产生远端副作用的操作进入同一操作前向恢复。
- 历史记录可支持后续审计和显式对象生命周期治理，但不能被普通预览过期清理误删。
