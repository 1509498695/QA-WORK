# 使用稳定登记引用标识受管工作表修订目标

首次受管工作表交付完成后，Provider 必须向调用方返回 opaque `registration_ref`，并在该工作表全部后续修订中保持它不变。`registration_ref` 是公开修订契约中的规范写入身份：Provider 用它从受管登记加载固定的 Provider Profile、工作簿稳定标识和工作表稳定标识；一次性的 `operation_ref`、工作表名称或用户可见链接都不能替代它。

飞书链接仍可作为用户输入，用于精确查找或交叉核验既有登记，但链接本身不授予修订写入能力。任何链接解析结果都必须唯一匹配同一 `registration_ref` 已绑定的工作簿和工作表，否则修订在零写入阶段失败。`registration_ref` 只标识受管对象，不替代每次修订的规范绑定、MCP 确认或当前用户授权。

## Considered Options

- 每次仅凭飞书 URL 选择修订目标：拒绝，因为 Wiki 跳转、工作表选择器缺失、链接替换和重名都可能把写入指向错误对象。
- 沿用首次交付的 `operation_ref`：拒绝，因为操作引用描述一次状态机执行，不应兼任跨多个版本的稳定对象身份。
- 由调用方传入工作簿 token 与 Sheet ID：拒绝，因为这会泄漏 Provider 私有定位细节，并允许调用方拼装未经登记的目标组合。

## Consequences

- 首次交付和每次成功修订的结果都必须返回同一 `registration_ref`；现有状态库中的登记引用从内部字段提升为公开非敏感引用。
- 修订预览不再接收放置模式，也不根据名称或 URL 重新选择写入目标；它从登记中加载受保护目标。
- 若调用方只有链接，必须先将其唯一解析为既有登记并核验稳定目标，不能绕过登记直接进入修订写入。
- 受管工作表被删除、替换、转移到不兼容主体或无法再唯一核验时，原登记引用保持可审计但不可继续写入。
