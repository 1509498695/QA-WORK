# 在用户指定的工作簿中仅管理一个工作表

Feishu Sheets 首个写入纵切允许用户提供直接 Sheets URL，或在线解析后真实类型为 Sheets 的 Wiki URL，作为目标工作簿。目标工作簿继续由用户拥有，Provider 不因获得链接和编辑权限而接管整个工作簿；每次交付只登记并管理一个确定的工作表。

受管工作表有两种建立方式：Provider 在目标工作簿中新建工作表，或在正式写入授权明确指向既有工作表、且 Provider 在预览和实际写入前都能证明该工作表满足内容空白判定时接管该工作表。内容空白要求目标是普通、可见的工作表，读取完整覆盖其网格，所有单元格都只包含空值或空字符串，并且没有公式、富文本、链接、提及或合并区间。行列尺寸、冻结和空单元格样式可以保留；声明交付区域内的样式可以由本次写入覆盖，区域外不得改动。登记至少绑定 Provider Profile、工作簿标识、工作表标识、创建或接管检查点及初始内容状态。后续修订只能作用于该登记工作表；同一工作簿中的其他工作表始终保持只读。

写入预览必须把工作表放置模式固定为“接管内容空白工作表”或“新建工作表”，并展示规范化目标工作簿、确定工作表或拟建名称、建立方式和预计变更范围。Provider 不得根据远端状态自动在两种模式间切换。

接管模式必须使用稳定工作表标识：直接 Sheets URL 含 `sheet` 查询参数时只允许定位该工作表；不含选择器时，仅在工作簿恰好只有一个普通、可见工作表时允许定位它；存在多个工作表即停止并要求精确链接。不得按工作表名称或位置猜测。新建模式只使用链接定位目标工作簿，即使链接含工作表选择器也不能修改或接管被选工作表。

新建模式必须由调用方提供拟建工作表名称，并把该名称绑定到预览和正式写入授权。预览时名称已存在即返回冲突；Provider 可以提出可用名称建议，但不得自行采用建议、追加后缀或替换用户确认的名称。若名称在预览后、执行前被占用，本次授权失效并要求重新预览。接管模式保留既有名称，不附带重命名。建立成功后，登记和回读以稳定工作表标识为准，名称只用于展示和冲突检查。

若目标链接不能解析为 Sheets、工作表选择不唯一、空白前置条件不再成立、目标工作表被替换或删除，或预览绑定的目标状态发生相关变化，正式写入授权立即失效并要求重新预览。新建工作表、初次内容写入和登记之间的部分成功必须通过同一幂等检查点恢复或对账，不能转而修改其他工作表，也不能静默再建一个工作表。

本 ADR 是 ADR-0006 要求的独立高风险语义：它只把受管边界从整个 Sheets 对象收窄为一个工作表，并不开放任意既有工作簿内容的原位修改。Docx 与普通 Wiki 正文写入不属于此纵切。

## Considered Options

- 接管用户指定的整个工作簿：拒绝，因为链接和编辑权限不能表达对所有既有工作表的业务授权，并会使后续修订误伤同簿内容。
- 只允许 Provider 新建全新工作簿：拒绝，因为不能满足用户在指定在线工作簿中新增 Sheet 或使用明确空白 Sheet 的交付方式。
- 允许覆盖任意既有工作表：拒绝，因为无法区分用户提供的空白交付目标与已有业务内容，且与 ADR-0006 的默认只读边界冲突。

## Consequences

- 公共写入契约、预览、授权、幂等键、登记记录和语义回读都必须包含稳定的工作表标识，不能只记录工作簿 URL 或名称。
- 资源定位模型必须保留并校验直接 Sheets URL 的 `sheet` 查询参数；只读读取仍可覆盖整个工作簿，但不得复用会丢失选择器的规范化结果作为写入目标。
- 工作簿中其他工作表的无关变化不应自动扩大或转移受管边界；目标工作表自身的相关变化必须使旧预览失效。
- 任何读取截断、读取警告、未知复杂单元格或不能证明内容空白的情况都必须拒绝接管；不得把视觉上看似空白等同于内容空白。
- 新建模式的名称是必填预览输入；同名冲突和竞态都不得通过自动改名绕过用户确认。
