# 使用有界语义差异确认受管工作表修订

受管工作表的一次 MCP elicitation 只展示精确目标和有界语义差异，不展开工作表正文。确认卡片必须包含工作簿、工作表、链接、当前用户主体、受管版本变化、旧新交付矩形、单元格新增修改清空计数、公式与合并增删计数、样式和行列尺寸及冻结变化、修订退役区域的精确范围与清理数量，以及完整 `preview_sha256`、`base_spec` 摘要和 `next_spec` 摘要。

上层业务 Skill 负责在发起写入前让用户审阅业务内容；Provider 卡片只负责把一次远端授权绑定到确定目标和不可变修订规范对。卡片不得转储单元格值或公式正文，以免超出 MCP 交互容量、泄漏业务内容或让关键破坏性范围淹没在大量文本中。摘要哈希不得截短，任何规范或目标变化都必须生成新的预览和确认。

## Considered Options

- 在确认卡片中展示完整旧新单元格正文：拒绝，因为大型 QA 表会使交互不可用，并扩大敏感内容暴露范围；内容审阅已经属于上层业务预览。
- 只显示工作表名称和“确认更新”：拒绝，因为用户无法看见版本、影响范围或退役清理，授权不能证明绑定了哪一版内容。
- 只展示截短哈希：拒绝，因为截短标识不适合作为跨层精确预览引用，且会削弱审计可比性。

## Consequences

- Provider 需要在零写入阶段计算确定性的语义差异摘要，并把它连同目标和规范摘要纳入 `preview_sha256`。
- 确认消息必须对破坏性清理优先展示精确范围，普通计数保持紧凑；差异计算也必须能明确表示零变化，不能伪造变更。
- 业务 Skill 不能把 Provider 的授权摘要冒充完整内容预览，也不能跳过其自身的业务审阅责任。
- 日志和错误详情同样不得为了调试而输出完整单元格正文。
