# 使用 Sheets API 与临时 XLSX 导出双重验证交付

Feishu Sheets 当前原生读取能力可以回读工作表身份、值、公式、合并、网格边界和冻结状态，但公开方法列表没有提供与样式写入对应的单元格样式读取，也不能完整回读行高和列宽。首个写入纵切仍需兑现 ADR-0010 与 ADR-0046 的样式和尺寸语义验证，因此在写入步骤完成后，Provider 使用同一用户 Profile 创建一次 `sheet` 到 `xlsx` 的 Drive 导出任务，查询完成后把导出文件下载到受限内存，解析目标工作表并立即释放全部字节。

验证同时使用两条证据链。Sheets API 重新读取稳定工作表标识、标题、值、公式、合并、网格边界、冻结状态和 revision；XLSX 只解析目标工作表的公式、合并、白名单样式、行高、列宽和冻结状态。两者分别规范化并与已授权工作表交付规范比较，且相互重叠的语义必须一致。任一读取不完整、导出任务失败或超时、文件超过安全上限、目标工作表映射不唯一、解析出现未知结构或比较不匹配，都返回 `verification_incomplete` 或恢复状态，不得声明 `delivered`。

XLSX 的两个格式细节必须按文件模型而非普通单元格直觉比较。合并区域的边框由 openpyxl 聚合到左上锚点，并把外缘传播到其余 `MergedCell`；校验器据此重建可见外框。列宽在 XLSX 中是相对于工作簿 `Normal` 字体的字符宽度，不是像素；校验器从受支持的默认字体与字号换算最大数字宽度，并只接受不超过半个字符宽度的整数化误差。默认字体未知、宽度偏差超过该界限或其他格式语义不匹配时仍然失败，不得用宽松的固定百分比容差跳过验证。

导出链的创建、轮询、下载和语义比较分别产生有界的安全诊断码；平台任务终态、下载大小不一致以及首批结构化 XLSX 差异必须能够区分。诊断码不得包含访问令牌、文件内容或飞书返回的自由文本，并必须满足操作状态库的长度与字符白名单约束。若进程在 `api_verified` 后中断，最终对账发现的是确定性的 XLSX 验证差异，应把操作收敛到非歧义的 `verification_incomplete`，保留具体诊断并允许下次只重做回读，不能永久停留在泛化的 `interrupted_execution`。

最终 `delivered` 证据哈希由规范哈希、API 回读哈希和 XLSX 回读哈希共同计算并持久化。相同操作的后续幂等查询必须返回同一交付证据哈希，不能退回预览哈希；旧状态库缺少该字段时自动迁移，并在不执行写入的前提下重新双重回读一次完成回填。回填失败时保留既有终态，但 `retrieval_complete` 必须为假并报告证据刷新警告。

创建和下载导出任务需要在现有写入能力之外为 Provider Profile 增加 `drive:export:readonly`（或平台当前等价的最小导出 Scope），并经过独立增量 OAuth 和客户端 Profile 能力检查。XLSX 导出包含整个工作簿，因此写入预览与 MCP 确认必须明确披露整簿内容会短暂进入 Provider 进程内存；Provider 不解析非目标工作表的业务内容，不把导出文件写入磁盘、任务暂存区、操作状态库、日志或恢复胶囊。

## Considered Options

- 只使用样式写入响应中的数量和 revision：拒绝，因为成功响应不能证明最终单元格样式、行高和列宽符合期望。
- 首版取消全部样式和尺寸：拒绝，因为已经确认的单工作表规范需要表达 A:J 用例表的核心版式。
- 把导出的 XLSX 保存为审计附件：拒绝，因为它包含目标工作簿的其他工作表，超出最小验证与持久化边界。
- 只依赖 XLSX 导出回读全部语义：拒绝，因为导出转换可能规范化工作表内容，且稳定 Sheet ID 和 Provider revision 仍需直接 API 证据。

## Consequences

- 写入语义能力的 Scope 映射和预检必须同时覆盖 Sheets 编辑、Sheets 读取和 Drive 导出；已有只读 Profile 需要增量 OAuth。
- MCP runtime 必须包含受控 XLSX 解析依赖、下载字节上限、轮询期限、工作表映射规则和恶意压缩包防护测试。
- 合并边框、字体相关列宽换算、安全诊断长度以及中断后验证恢复必须有独立回归测试；不能以扩大固定容差替代格式模型校准。
- 导出文件十分钟有效期只约束远端临时产物，不授权本地持久化；Provider 应在取得后立即验证并释放。
- 若飞书未来提供可精确回读全部所需样式与尺寸的原生接口，可以通过新证据替换导出路径，但必须先证明语义等价并更新 ADR。
