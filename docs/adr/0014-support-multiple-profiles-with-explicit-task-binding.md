# 多 Profile 能力通过任务主体绑定消除歧义

Provider 契约从首版支持多个 Profile，每次任务在预检阶段绑定确定的 `profile_ref` 和脱敏用户主体，并将该身份延续到预览、正式写入授权、远端操作及审计结果。仅存在一个明确配置的默认 Profile 时可以自动绑定，但预览必须展示其执行账号；存在多个可用 Profile 且任务没有明确绑定时返回 `profile_selection_required`，等待用户选择，不得根据资源链接、最近使用记录、历史任务或凭证库顺序猜测。

## Considered Options

- 首版契约只支持一个账号：拒绝，因为后续增加多账号会破坏任务、授权和受管对象的主体字段。
- 多账号时自动选择最近使用账号：拒绝，因为同一链接可能被多个账号访问，历史选择不能构成本次身份授权。
- 由业务 Skill 保存并切换账号：拒绝，因为账号选择会脱离 Provider 的凭证、预检和审计边界。

## Consequences

- Profile 绑定发生变化时，原任务预检、预览和正式写入授权全部失效；继续操作必须重新预检和确认。
- `profile_selection_required` 与 `auth_required` 含义不同：前者尚未确定主体，后者主体已确定但授权不可用或不足。
- 受管交付对象登记必须保留创建它的 Profile 与稳定用户主体引用，后续修订不得由另一个 Profile 静默接管。
