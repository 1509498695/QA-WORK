# 在授权控制面浏览器页面确认客户端 Profile 绑定

客户端 Profile 绑定的新建和能力扩大必须通过飞书授权控制面的浏览器确认流程完成。已登记执行客户端先以 mTLS 创建短时、单次的 `binding_request`，客户端身份从验证后的证书取得，并提交目标 Profile 引用和请求的稳定语义能力 ID；控制面返回不透明请求引用、同源确认入口和过期时间。业务 Skill 或对话只能向用户展示该入口与非敏感请求摘要，不能提交批准结果、代替用户点击确认或把自然语言“确认”转换为绑定授权。

用户打开确认入口后，控制面必须在自身稳定 HTTPS Origin 内独立验证飞书用户身份，并确认该主体、目标 Profile 和准入 `tenant_ref` 一致。确认页面必须展示客户端名称、`client_ref`、证书指纹摘要、Profile 主体、当前绑定能力和本次新增能力；用户只能对这份不可变请求批准或拒绝，任一展示字段或能力集合变化都会使原请求失效。OAuth 登录或增量 Scope 流程可以由该页面按需引导，但 Profile OAuth、绑定批准和 Scope 授予仍保存为不同状态与审计事件。

批准或拒绝后，控制面只在服务端提交绑定修订和审计记录。执行客户端使用原证书通过 mTLS 轮询该请求，只能取得 `pending`、`approved`、`denied`、`expired` 或 `consumed` 状态，以及获批绑定的最小引用和能力摘要；浏览器 URL、OAuth 回调、对话消息和轮询结果都不得携带 App Secret、Refresh Token 或 User Access Token。短期访问令牌只能在绑定生效后通过独立租约请求取得。

## Considered Options

- 用户直接在 Codex 对话中确认绑定：拒绝，因为控制面无法证明发言者就是目标飞书 Profile 主体，也无法把自然语言可靠绑定到客户端证书和能力差异。
- OAuth 回调成功后自动绑定当前客户端：拒绝，因为身份验证或 Scope 同意不表示用户已审阅并批准该设备及其语义能力集合。
- 浏览器把授权码或 Token 重定向回本机客户端：拒绝，因为长期凭证边界会重新落到本机，且回调和令牌泄漏面扩大。
- 客户端轮询时返回 User Access Token：拒绝，因为绑定状态查询与短期令牌租约具有不同条件、生命周期和审计含义。

## Consequences

- `binding_request` 必须保存请求字段摘要、创建客户端、目标 Profile、能力差异、过期时间、单次消费状态和最终批准主体；请求引用必须高熵、短时且不可用于枚举其他请求。
- 浏览器会话必须具备 CSRF、防重放、OAuth `state` 校验和安全 Cookie 等 Web 安全控制；确认请求过期、已消费或字段摘要不匹配时必须重新发起。
- 执行客户端可以在对话中启动流程、展示入口和报告结果，但不能声称用户已授权，直到 mTLS 轮询取得控制面记录的 `approved` 状态并重新执行预检。
- 用户在对话中选择本地或飞书交付以及确认确定内容的正式写入仍遵循 ADR 0008；本 ADR 只处理客户端与飞书 Profile 的长期能力绑定。
- 浏览器入口的具体页面样式、通知方式和绑定固定有效期分别决策，不改变服务端确认边界。
