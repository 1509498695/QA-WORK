# 按任务即时签发短期访问令牌租约

飞书授权控制面只在执行客户端即将为确定任务调用 Feishu Provider 时签发短期访问令牌租约。每份租约必须绑定 `tenant_ref`、经 mTLS 认证的 `client_ref`、`profile_ref`、逻辑 `task_ref`、请求的稳定语义能力集合、客户端 Profile 绑定修订和签发时的 Profile Scope 快照；缺少任务引用、跨租户、绑定无效、能力越界或 Scope 不足都不得交付 User Access Token。`task_ref` 用于隔离和审计关联，不因被写入租约而成为秘密或单独授权。

一个客户端可以在同一任务、同一 Profile、同一能力集合和同一有效租约内执行多次受控语义操作，但不同任务不得共享租约，任务改变 Profile 或扩大能力集合时必须重新预检并申请新租约。客户端只能在该租约对应任务的进程内存中持有飞书 User Access Token，不得把令牌存入本机凭证库、磁盘缓存、任务 manifest、环境变量、子进程参数、日志、MCP 参数或结果；任务结束、租约到期、Provider 进程退出或租约被客户端判定失效时立即清除内存引用。

授权控制面可以为同一 Profile 安全缓存、刷新并在内部复用飞书签发的 User Access Token，但每个客户端任务仍获得独立 `lease_ref` 和审计记录。多个租约在技术上可能承载同一个飞书 Bearer Token 值，控制面和客户端不得因此声称该 Token 已被飞书按任务降权或证书绑定；任务租约是本平台的交付、使用和审计合同，不改变飞书资源服务器实际识别的 Token 权限。客户端不得因为曾见过相同 Token 值而绕过新任务租约。

## Considered Options

- 客户端登录后持有可跨任务复用的 Token 会话：拒绝，因为任务、Profile、能力请求和审计边界会消失，过期设备也会长期保有用户访问能力。
- 每个 Feishu API 请求都签发新 Token 租约：拒绝，因为同一任务的分页、附件读取和语义回读会产生大量无意义租约，而飞书底层 Token 值通常不会随每次请求改变。
- 客户端自行刷新 User Access Token：拒绝，因为这要求向本机下发 App Secret 或 Refresh Token，违反 ADR 0023 的长期凭证边界。
- 把 `task_ref` 当作租约访问密钥：拒绝，因为任务引用会出现在本地 manifest 和审计记录中，本来就不是秘密或身份凭据。

## Consequences

- 租约记录必须包含 `lease_ref`、任务与身份绑定、能力集合、绑定修订、Scope 快照、签发时间、租约到期时间、飞书 Token 实际到期时间、状态和审计关联，但不得保存或输出明文 Token 到普通审计日志。
- 租约有效期、同任务续租和控制面故障行为遵循 ADR 0031：最长十分钟，每次续租完整重检，新租约与续租在故障时失败关闭。
- 控制面不可用时客户端不得把旧租约提升为新任务租约，也不得从磁盘恢复历史 Token；仅可在 ADR 0031 的边界内用完当前任务尚未到期的租约。
- 本任务结束后，控制面可以保留不含明文 Token 的租约审计，客户端不得保留可恢复的令牌副本。
