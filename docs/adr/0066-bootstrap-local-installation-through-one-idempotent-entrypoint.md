# 通过一个幂等入口完成本机初始化

普通 QA 拉取 QA Skill Hub 后，只运行一个本机初始化入口。该入口在当前用户范围内协调 Provider Plugin、业务 Skill 发现入口、必要运行依赖、中央服务入口和首次只读能力验证；首次安装、缺失修复与已发布版本升级复用同一流程。用户主动运行该入口即授权这些本机安装变更，不再对 Marketplace 登记、Plugin 安装和 Skill Junction 分别增加产品确认。

初始化器只消费当前检出仓库已有的 Plugin manifest、个人 Marketplace 和规范 Skill 目录，不新增自定义 Workspace 清单，不主动执行 `git pull`，也不从仓库之外猜测最新版本。平台管理员负责发布已经完成同一提交内自检的仓库版本；本机流程负责把安装状态收敛到该检出版本。没有变化时静默通过，安全可修复的缺失或旧版本直接修复，遇到同名非受管内容、无法确认来源或当前版本自检失败时停止且不得覆盖。

流程必须区分安装完成、中央服务可达、用户 OAuth、团队成员资格和业务能力可用。成功标准是只读能力声明与任务预检通过；安装成功不授予角色、不建立团队关系，也不跳过飞书 OAuth 或正式写入确认。升级采用先验证后切换的方式，失败保留最后一个已验证版本，并给出一个主要恢复操作、稳定错误码和诊断摘要。

## 被拒绝的方案

- 继续让用户分别运行 Skill Junction 脚本、Marketplace 命令并手动重载 Plugin：拒绝，因为普通 QA 必须理解实现细节，且无法得到统一的首次成功结论。
- 初始化器自动拉取 Git 或安装互联网上的任意最新版本：拒绝，因为它把源码更新、版本发布与本机安装混为一体，无法保证兼容性和可恢复性。
- 把 Plugin、业务 Skill 和中央身份打包成一个不可分割授权步骤：拒绝，因为安装状态不能证明用户身份、团队归属或外部资源权限。
- 为协调版本新增 `workspace.yaml`：拒绝，因为现有标准 manifest 和目录已经表达安装来源，重复清单会形成第二真源。
