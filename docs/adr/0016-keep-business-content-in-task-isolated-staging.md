# 将完整业务内容归属任务隔离暂存区

外部来源的完整正文、结构、表格、图片、附件和规范化证据归属调用方业务任务，并固化到该任务的隔离暂存区，形成不可变且带完整性校验的任务内容快照。Provider 可以执行读取和规范化，但不得把完整业务内容保存在自身常驻状态中，也不得建立可被其他任务命中或复用的正文与附件缓存。同一任务需要重复处理时只能引用同一个已校验快照；来源发生变化时形成新的快照版本，不覆盖原快照。

Provider 常驻状态只允许保存执行公共能力所必需的最小技术信息，包括 Profile 引用、稳定资源定位、内容哈希、快照清单引用、受管对象登记和幂等检查点，不保存快照正文或附件。只有远端写入已经开始且结果无法判定时，Provider 才能创建与任务、主体、目标、操作和授权绑定的加密恢复胶囊；胶囊仅包含恢复对账所需的最小状态，不得参与普通读取、搜索或跨任务复用。

## Considered Options

- 由 Provider 集中缓存所有来源正文和附件：拒绝，因为公共服务会累积多个业务 Skill 的敏感内容，并模糊内容所有权、保留周期和访问边界。
- 每次处理都重新读取外部实时资源：拒绝，因为任务期间来源可能变化，无法证明分析、预览和交付使用的是同一份证据。
- 允许不同任务按资源地址或内容哈希共享完整缓存：拒绝，因为相同资源在不同主体、授权和任务中的可见边界可能不同，内容相同也不代表可跨任务披露。

## Consequences

- 业务 Skill 必须为每个任务提供隔离暂存边界，并通过快照清单和内容哈希引用证据；不得只保存飞书链接作为正式来源。
- Provider 返回的资源定位和哈希可以进入最小技术状态，但完整正文、图片和附件只能存在于对应任务的快照边界内。
- 快照版本变化会使依赖旧内容的预览、正式写入授权和交付计划失效。
- 任务快照与恢复胶囊采用不同生命周期；二者具体保留时长和清理规则分别决策，不能因任务结束而默认互相删除。
