# 已交付必须通过资源类型专属语义回读

公共能力契约使用统一的交付结果包络，但只有资源类型专属语义回读全部精确匹配时才能返回 `delivered`：Docx 核对标题、正文块顺序、文本、表格以及图片和附件引用；Sheets 核对标题、Sheet 名称与顺序、声明的目标区域、值、公式、合并和必要样式；本地文件核对文件哈希及对应格式的结构合同。签名在平台允许的标准化规则后比较，不要求远端响应与请求字节相等；对象创建、写请求成功、抽样匹配或部分回读均不得映射为已验证交付。

## Considered Options

- 以 API 成功响应作为交付完成：拒绝，因为请求成功不能证明最终远端内容、公式计算或结构状态正确。
- 所有资源统一比较原始字节：拒绝，因为远端平台会规范化内容表示，且不同资源的关键业务语义并不相同。
- 只回读少量代表字段：拒绝，因为未覆盖区域、顺序、公式、合并或附件仍可能失败，却会被误报为成功。

## Consequences

- 公共结果包络必须分别携带预期语义签名、实际回读签名、验证状态和可定位的不匹配项。
- 回读不完整或不匹配时进入验证失败或恢复流程，不得保留 `delivered`。
- 新增交付资源类型时，必须先定义并测试其语义回读合同，不能复用与其不相符的通用成功判断。
