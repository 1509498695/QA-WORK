# 在本机操作状态库持久化最小写入状态

ADR-0044 的本机单用户写入纵切在 MCP 执行端新增一个私有操作状态存储接口，并首先实现为 `%LOCALAPPDATA%\WorkspaceCapabilities\providers\feishu\operations-v1.sqlite3`。该位置延续 ADR-0043 的既有兼容性命名空间，但文件身份、Schema 和迁移由当前 Feishu Provider 独立拥有。OAuth 控制面继续只管理应用绑定、Provider Profile 和短期令牌租约，不接收工作表正文或写入计划。

操作状态库持久化十分钟有效的预览摘要、服务端单次授权状态、幂等操作及步骤状态、受管工作表登记、未解决恢复记录和最终恢复墓碑。工作簿 token、工作表标识及恢复所需定位载荷使用当前 Windows 用户 DPAPI 保护；可查询键只保存不可逆摘要和非敏感引用。所有状态转换使用事务和明确版本，保证进程退出或插件重启后仍能识别同一操作，不能因内存丢失而重复新建或覆盖其他工作表。

工作表交付规范及其正文不进入操作状态库。调用方任务暂存区继续拥有不可变规范快照；正式应用和恢复对账必须重新提交同一 Schema 版本的规范，Provider 规范化并验证其内容摘要与记录一致后才能继续。预览过期后可以删除其最小记录；受管工作表登记、处于不确定状态的操作和恢复墓碑不得因时间经过自动删除。已解决状态的保留和显式清理可以在后续治理设计中收紧，但不能删除当前恢复证据。

## Considered Options

- 所有状态只放在 MCP 进程内存：拒绝，因为进程退出会丢失受管边界和部分成功检查点，随后可能重复创建或写入。
- 把完整交付规范保存在 Provider 数据库：拒绝，因为业务正文属于调用方任务，并会让通用 Provider 累积跨任务敏感内容。
- 把操作状态交给 OAuth 控制面保存：拒绝，因为控制面不代理业务正文或远端资源操作，本机开发纵切也不应扩大其数据职责。
- 使用调用方任务目录作为唯一操作数据库：拒绝，因为 Provider 无法跨任务可靠限制受管对象和恢复锁，也会把 Provider 私有状态合同泄漏给每个业务 Skill。

## Consequences

- 必须实现版本化数据库迁移、事务状态机、并发锁定、损坏时失败关闭和不含正文的安全诊断。
- 正式应用和恢复工具必须要求调用方重交规范；找不到正文时只能报告恢复所需输入，不能绕过摘要校验。
- Provider Plugin 更新和仓库重构不得移动、覆盖或重建该数据库；测试使用隔离临时库和伪 DPAPI 保护器。
- 未来中央部署可以替换私有存储实现，但必须迁移受管登记、未解决操作和恢复墓碑，并保持公开语义合同不变。
