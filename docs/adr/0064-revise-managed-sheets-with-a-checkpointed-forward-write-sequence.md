# 通过固定检查点序列前向修订受管工作表

用户接受一次修订确认后，Provider 按固定顺序把受管工作表从已验证 `base_spec` 迁移到 `next_spec`：先锁定登记和候选受管版本并按需扩展网格；拆除基线中的旧合并；写入目标完整矩形并清空修订退役区域；清理并重建目标样式；写入目标尺寸并把完全退役行列重置为 Schema v1 固定中性值（行高 `24 px`、列宽 `100 px`）；写入冻结设置；最后建立目标合并。随后执行 API 与临时 XLSX 双重验证，只有验证完整时才把受管登记指针前移到候选版本。

每个远端变更阶段都有持久幂等检查点。任一步结果明确失败但尚未改变远端时可以安全停止；已完成部分步骤或结果不明时，操作进入 `recovery_required` 或 `verification_incomplete`，只允许以同一 `operation_ref`、登记引用和规范对进行回读对账及安全前向恢复。恢复不回滚、不切换目标、不创建竞争版本、不再次确认，也不盲目重放无法证明未完成的步骤。

## Considered Options

- 在旧合并仍存在时直接覆盖目标矩形：拒绝，因为合并单元格可能阻碍完整矩阵写入，也会让旧新合并差异难以幂等处理。
- 先建立新合并再写值和样式：拒绝，因为后续批量写入可能无法覆盖合并区域内的完整语义。
- 失败时自动恢复 `base_spec`：拒绝，因为回滚是第二次破坏性远端写入，可能再次失败或覆盖确认后的并发变化，且与 ADR-0051 的前向恢复边界冲突。

## Consequences

- 操作状态库需要修订专用步骤枚举，并为拆合并、退役清理、目标重写和候选版本前移分别建立检查点。
- 每个可能产生部分成功的批次必须返回可诊断的明确失败或歧义状态；恢复先回读现场再决定下一安全步骤。
- 候选版本在最终验证前保持未终结且独占登记，其他修订请求以写冲突零写入结束。
- 最终结果必须同时证明 `next_spec`、退役区域清理和稳定目标身份，单一写请求成功不等于交付完成。
