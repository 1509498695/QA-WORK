# 任务快照与审计证据保留到确认清理

业务任务达到结束状态后，其任务内容快照和审计证据只转换为只读、可清理状态，不自动删除，也不因成功交付、任务取消、进程退出或经过固定时间而推断用户同意清理。清理是独立的显式操作：执行前必须生成清理计划，列出任务标识、经过边界校验的绝对路径、项目数量、总大小、内容哈希或清单哈希，并取得绑定该计划的单次用户确认。计划范围或内容发生变化时，原确认失效。

清理实现必须先证明所有目标都位于被确认的任务边界内，不得使用未解析变量、通配符、工作空间根目录或跨任务目录作为清理目标。清理完成后保留不含业务正文的最小清理回执，记录计划哈希、执行结果和未清理项目；本决策不授权立即清理任何现有文件，也不预先决定采用回收站、隔离区或永久删除。

## Considered Options

- 任务成功或取消后立即自动删除：拒绝，因为任务结束不代表证据已不再需要，也没有用户对具体目标的清理授权。
- 按固定保留天数自动删除：拒绝，因为不同业务任务的复核、追溯和合规周期不同，单一时限会造成不可恢复的数据丢失。
- 由 Provider 顺带清理调用方任务内容：拒绝，因为 Provider 不拥有业务内容，也不应获得调用方任务目录的宽泛删除权限。

## Consequences

- 业务 Skill 必须显式展示任务快照的封存状态、占用空间和是否可清理，不能把它们隐藏为临时文件。
- 任务清理确认与正式写入授权相互独立，且只能覆盖清理计划明确列出的内容。
- 未获确认、路径越界、清单漂移或部分清理失败时必须停止并报告，不得扩大范围或自动重试剩余目标。
- 长期磁盘占用由可见的清理队列管理，而不是通过后台自动删除解决。
