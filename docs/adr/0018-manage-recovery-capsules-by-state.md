# 恢复胶囊采用状态驱动生命周期

恢复胶囊不按固定保存时长自动删除。远端写入处于 `possibly_modified` 或 `recovery_required` 时，Provider 加密保留与该任务、主体、目标、操作和正式写入授权绑定的最小恢复胶囊，并锁定同一操作与目标，阻止自动重试、新建替代对象或以另一业务 Skill 绕过恢复状态。只有恢复对账得出确定结果且不含业务正文的审计回执已经持久化后，Provider 才安全删除恢复胶囊，同时保留记录最终结果和原操作身份的恢复墓碑。

未能得出确定结果时，恢复胶囊只能在用户查看具体任务、目标、未知远端影响和胶囊摘要后，通过独立的“放弃恢复”确认移除。放弃后必须留下 `recovery_abandoned` 恢复墓碑；原正式写入授权永久失效，系统不得自动重放。后续若仍需写入，必须作为新的操作重新读取可见远端状态、形成预览并取得新的正式写入授权，同时显式展示先前状态仍不确定的风险。

## Considered Options

- 到达固定 TTL 后删除所有恢复胶囊：拒绝，因为时间经过不能证明远端没有被修改，删除唯一检查点会诱发重复写入。
- 对账一失败就要求用户重新执行写入：拒绝，因为原请求可能已经成功落地，新写入可能产生重复对象或覆盖内容。
- 永久保留已经解决的恢复胶囊：拒绝，因为确定结果和最小审计回执已经足够，继续保存敏感恢复状态违反最小保留原则。

## Consequences

- Provider 必须维护恢复胶囊状态、目标锁和恢复墓碑，并保证它们的状态转换具有幂等性。
- 安全删除胶囊的前置条件是确定的恢复结果和持久化审计回执，而不是进程退出、任务结束或时间到期。
- `recovery_abandoned` 不是 `failed_no_change`；任何界面、Skill 或审计都必须保留未知远端影响提示。
- 恢复墓碑只保存任务、主体、目标、操作、授权摘要、结果状态和时间等最小技术字段，不保存正文、附件或可用于重新执行写入的载荷。
