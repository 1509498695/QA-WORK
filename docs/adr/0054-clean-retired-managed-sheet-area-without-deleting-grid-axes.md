# 缩小受管工作表时清理退役区域但不删除网格行列

当同一受管工作表从较大的 `base_spec` 交付矩形修订为较小的 `next_spec` 交付矩形时，Provider 必须把旧矩形减去新矩形所得区域视为修订退役区域。只有严格无漂移前置检查通过后，Provider 才能清除退役区域内上一版交付的值、公式、链接、富文本和样式，拆除进入退役区域的旧合并，并把完全退役行列的尺寸恢复为 Schema v1 固定中性值：行高 `24 px`、列宽 `100 px`；不得物理删除工作表行列，也不得修改旧交付矩形之外的区域。

这项清理是同一稳定工作表从旧验证状态迁移到新验证状态的一部分，而不是对矩形外空白区的一般管理权。飞书 `style.clean=true` 的成功响应不能单独作为退役样式已清除的证据；Provider 在清理后显式写入左对齐、上对齐、无边框、默认格式和清理字体的中性样式，并接受 XLSX 将其表示为 `left` / `top`。旧版 `middle` 或其他业务样式仍视为残留。写后验证必须同时证明新交付矩形符合 `next_spec`、退役区域不再含有业务内容或跨界合并；未能完整证明时不得报告交付完成。

## Considered Options

- 只覆盖新交付矩形并保留旧尾部：拒绝，因为缩小后的用例表仍会暴露上一版内容、合并或视觉残留，无法表示完整的目标状态。
- 物理删除退役行列：拒绝，因为删除会改变网格结构和索引，扩大对同一工作表的破坏范围，也增加恢复与审计复杂度。
- 清理新矩形以外的整个工作表：拒绝，因为受管权限只来自上一版已确认的交付矩形，不能外溢到从未由 Provider 管理的空白区域。

## Consequences

- 修订预览必须明确展示退役区域、将被清除的内容范围、受影响合并以及完全退役的行列尺寸，不能把缩小描述成普通覆盖。
- 清理范围必须由已认证的 `base_spec` 与 `next_spec` 确定，不能根据远端已用区域或工作表总网格推断。
- 写入与恢复流程需要为拆除旧合并、清空退役内容、清理样式和重置退役尺寸建立可幂等检查点。
- 工作表稳定标识、链接和网格行列数量保持不变；修订只改变上一版明确受管的语义。
