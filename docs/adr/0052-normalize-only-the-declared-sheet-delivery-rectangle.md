# 只完整归一化声明的工作表交付矩形

工作表交付规范必须声明一个从首行首列开始的连续交付矩形，并给出矩形内的完整期望状态。Provider 在该矩形内写入值与公式，建立全部合并，应用基础样式和覆盖样式，并把涉及的行高、列宽与冻结状态归一化到规范；未显式覆盖的单元格和尺寸使用规范中的默认值，不能继承被接管空白工作表的偶然格式。任何合并范围必须完全位于矩形内。

交付矩形之外仍属于同一受管工作表的安全边界：Provider 必须证明那里没有值、公式、富文本、链接、提及或合并，但不清除、不重设也不回写只作用于空单元格的既有单元格样式。行高和列宽是整行/整列属性而不是单元格属性：交付矩形覆盖的前 N 行和前 M 列属于交付轴范围，其尺寸由规范归一化；第 N 行之后的行高和第 M 列之后的列宽保持不变。新建工作表的其他区域保持飞书默认状态。冻结设置同样是工作表级结构，由规范完整声明并允许覆盖接管前的冻结状态。

语义回读只把交付矩形内的内容、样式和尺寸以及工作表级冻结设置视为交付期望；同时继续证明矩形外不存在业务内容或跨界合并。矩形外既有纯格式差异不构成交付失败，也不得被表示为 Provider 已交付的格式。

## Considered Options

- 归一化整个工作表网格：拒绝，因为飞书工作表网格可能很大，清除全部空白样式既昂贵又会改变用户未授权的视觉状态。
- 只写非空单元格和显式样式：拒绝，因为接管模式会泄漏原有格式，使同一规范在新建与接管模式得到不同结果。
- 把矩形外纯格式也纳入严格相等验证：拒绝，因为该区域不属于交付内容，且当前原生 API 不能低成本完整枚举所有空白单元格样式。

## Consequences

- Schema 必须包含矩形行列数、基础样式、默认行高与默认列宽，并以范围覆盖表达例外。
- 写入前检查和写入后回读都必须拒绝矩形外业务内容及跨界合并；未知或读取不完整时失败关闭。
- 接管模式可以保留矩形外空白单元格样式以及交付轴范围之外的行列尺寸，但结果和审计必须明确这些格式不属于交付保证。
- 后续修订同一受管工作表若改变矩形大小，缩小后遗留内容的清理语义需要单独设计；首个纵切只处理初次交付。
