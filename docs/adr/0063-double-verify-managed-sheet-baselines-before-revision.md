# 修订前双重验证受管工作表基线

每次实际修订和无变化修订都必须在任何写入授权之前，以 `base_spec` 对同一受管工作表完成 API 回读与临时 XLSX 导出双重语义验证。API 证据负责值、公式、合并、冻结和矩形外业务空白；XLSX 证据补充验证样式、行高与列宽。只有两路证据都完整且一致时，远端状态才被认定为修订基线无漂移。

XLSX 只在当前 Provider 调用内存中短暂用于解析验证，不保存为本地交付文件，也不进入调用方审计包。导出创建、轮询、下载或解析任一步无法形成完整证据时，实际修订与无变化请求都以 `baseline_verification_incomplete` 结束并保持远端零写入；不能降级为 API-only，也不能要求用户用额外确认覆盖证据缺口。实际写入完成后仍按 ADR-0050 再执行一次 API 与 XLSX 双重验证最终状态。

## Considered Options

- 修订前只依赖登记中的飞书 revision：拒绝，因为 revision 不能证明具体受管语义，也可能受同工作簿其他变化影响。
- 修订前只使用 API 回读：拒绝，因为当前原生回读不能完整证明受管样式和行列尺寸未被人工修改。
- 只在写后做双重验证：拒绝，因为届时可能已经覆盖未经本流程确认的人工格式或尺寸变化。

## Consequences

- 每次实际修订通常产生一次写前导出和一次写后导出，增加请求耗时但不增加用户交互门禁。
- `no_change` 路径同样需要完整基线证据，不能仅比较两份调用规范摘要后短路。
- 授权 Scope 和能力声明继续明确临时导出用途；不得宣称其用于生成或保存本地 Excel 文件。
- 写前和写后 XLSX 验证应复用同一解析与诊断合同，避免再次出现无法定位的笼统验证失败。
