# 容许受管工作表展示元数据变化

严格无漂移前置条件只约束受管工作表的业务内容、结构、冻结设置、交付尺寸和稳定对象边界。只要工作簿 token 与 Sheet ID 仍匹配同一受管登记，工作簿或工作表重命名、工作表索引变化和排序调整属于允许的展示元数据变化；Provider 在修订预检中自动刷新当前名称和索引，并在确认卡片中展示它们，不因此建立新受管版本或要求用户额外确认。

工作表被隐藏、删除、替换为不同 Sheet ID、稳定工作簿身份变化或当前用户主体失去访问能力不属于展示变化，修订必须失败关闭且保持零写入。修订规范不包含重命名语义，Provider 也不得借修订流程把名称恢复成登记中的旧值。

## Considered Options

- 把任何名称或排序变化都视为基线漂移：拒绝，因为名称不是受管写入身份，用户整理工作簿会产生无业务意义的阻断和重复确认。
- 完全忽略所有工作表元数据变化：拒绝，因为隐藏、删除、替换和访问主体变化会改变可见性或对象边界，继续写入可能违反用户意图。
- 把工作表名称加入 `next_spec` 并由每次修订归一化：拒绝，因为本纵切管理工作表内容而不是工作簿导航结构，重命名需要独立显式语义。

## Consequences

- 受管登记和并发检查必须使用稳定工作簿及工作表标识，名称和索引只作可刷新展示字段。
- 修订预检需要区分可容许元数据变化与对象不可用或身份变化，并返回不同诊断。
- 确认卡片和最终结果显示调用时的当前名称，历史版本记录仍可保留当时的展示快照用于审计。
- 现有工作表名称发生变化时，Skill 无需向用户增加修复步骤。
