# 非原子空白工作表接管仅限本机开发纵切

当前核对到的 Feishu Sheets 写入接口会在响应中返回 revision，但新增工作表和范围更新合同没有提供可由调用方提交的预期 revision、可靠客户端幂等键或工作表互斥锁。因此，即使 Provider 在写入前完整证明目标工作表内容空白，也不能原子地阻止另一位编辑者在最终复核与首次远端写入之间修改同一工作表。

ADR-0044 的 `development_only` 本机单用户纵切允许显式接管模式承担这一残余风险。MCP elicitation 返回接受后，Provider 必须先重新读取目标工作表，重新证明工作表身份、读取完整性和内容空白与预览一致，然后立即开始已授权操作；发现任何漂移都保持零写入并要求重新预览。预览和确认卡必须明确显示非原子接管警告，调用方默认推荐新建工作表模式，不能把最终复核描述为并发锁或条件写入。

任何写请求结果不明都遵循 ADR-0009：记录 `possibly_modified`，锁定原目标并先对账，禁止盲目重试、改为新建或覆盖另一工作表。该例外不自动进入正式多人版本；在没有飞书条件写入、可靠资源锁或等价证明前，正式版本默认关闭接管既有空白工作表，只开放新建工作表和已登记对象的受控修订。

## Considered Options

- 把两次连续空白读取当作原子保证：拒绝，因为两次读取之间及第二次读取之后仍可能发生并发写入。
- 通过临时标记单元格模拟锁：拒绝，因为写标记本身也是无条件写入，不能防止并发编辑，并会改变用户对象。
- 首版完全删除接管模式：暂不采用，因为用户已明确要求本机开发纵切支持空白 Sheet 链接，且风险可以通过显式模式、即时复核和开发态标记限制。

## Consequences

- 接管模式的预览结果必须携带机器可读的 `non_atomic_blank_adoption` 风险标记；业务 Skill 不得隐藏或改写该警告。
- 新建模式不继承该空白接管警告，但名称竞态和结果不明仍按预览失效与恢复对账处理。
- 正式生产验收不能以本机接管成功作为并发安全证据；启用前必须单独重新评估平台能力并形成新 ADR。
