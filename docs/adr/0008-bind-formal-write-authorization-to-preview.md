# 正式写入授权精确绑定交付预览

本地构件库和外部系统 Provider 的正式写入都必须消费一份短期、单次的正式写入授权；该授权只在用户查看预览后产生，并绑定任务、通道、目标或容器、创建或修订动作、执行主体、内容哈希及预览版本。用户较早表达的“写本地”或“写飞书”只构成交付意向；绑定字段、目标当前状态或内容发生变化时授权立即失效，必须重新生成预览并确认。任务暂存区中的来源快照、审计证据和预览写入不属于正式交付，不消费该授权。

## Considered Options

- 业务 Skill 传入 `confirmed=true`：拒绝，因为 Provider 无法证明用户确认了哪个目标、哪份内容或哪个执行身份。
- 通道选择和最终内容分别确认两次：拒绝，因为一次在完整预览后的原子确认已经能同时表达通道选择和精确写入授权，额外交互没有增加证据强度。
- 在同一任务中持续复用一次确认：拒绝，因为后续生成变化或远端状态变化会使原确认失去对应对象。

## Consequences

- 公共能力契约必须让预览结果和正式写入授权共享稳定摘要，执行端不得重新解释或替换待写内容。
- 本地与飞书交付使用同一授权语义，但各自负责验证自身目标状态和完成回读。
