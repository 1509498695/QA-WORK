# 分离用户委托身份与 Provider 应用身份

飞书 Provider 对用户提供的来源、目标和用户归属资源使用当前用户明确授权的 `user_access_token`，仅对 Provider 自有模板、登记信息等内部资源使用应用身份；Token 的获取、刷新、保存与注销全部由 Provider 私有管理，业务 Skill 只接收脱敏的身份状态和稳定主体标识。用户 OAuth 缺失、过期、Scope 不足或主体不匹配时必须返回 `auth_required` 或等价受控状态，即使应用身份恰好具有访问能力也不得静默替代。

## Considered Options

- 所有操作统一使用应用身份：拒绝，因为用户内容的权限、归属和审计主体会被错误扩大或改写。
- 用户身份失败时自动回退应用身份：拒绝，因为同一业务操作会在用户不知情时改变执行主体和可见资源范围。
- 将 Token 交给业务 Skill 自行调用：拒绝，因为凭证会跨业务边界扩散，刷新、撤销和最小权限无法集中治理。

## Consequences

- 每次远端操作必须绑定稳定的用户主体或 Provider 应用主体，并在审计结果中保留脱敏主体引用。
- 应用身份只读到或写入哪些内部资源，由飞书 Provider 私有登记控制，不能由业务 Skill 传入任意资源标识扩大。
